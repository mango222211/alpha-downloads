4.15.1 업데이트

4.15.0 배포 이후 쌓인 수정을 묶은 업데이트입니다. 서버 쪽 변경(무료 한도 30,000, 검색 보정, 안내문, 굵게 강조, 기존 계정 닉네임 팝업)은 alphaaiweb.com 서버 재시작으로 적용되며, 앱 쪽 변경(단축키 표시, 패널 스크롤바, 라이브 크롭 우선순위, 검색 승인 단순화)은 이 버전부터 동작합니다.

요금·계정

  • 무료 계정 24시간 한도 30,000토큰으로 통일: 4.14.0에서 서버 한도만 128,000으로 올라가 화면에 "128,000 / 30,000"처럼 어긋나게 표시되던 문제. 사용자 결정에 따라 서버 한도(billing.FREE_LIMIT)·요금제 문구(전 언어)·한도 초과 오류 문구를 30,000으로 맞추고, 화면의 남은 토큰 표시는 고정값 대신 서버가 알려주는 한도(plan.limit)를 쓰도록 바꿨습니다(서버 재빌드 필요).
  • 기존 계정 닉네임 정하기 팝업: users.nickname_set 열(기본 0, 자동 마이그레이션)을 추가해 닉네임을 직접 정한 적 없는 계정(암호화 이전 가입자·소셜 프로필 이름으로 자동 등록된 계정)은 로그인 후 "닉네임 정하기" 창이 한 번 뜹니다(현재 이름 미리 채움, "지금 이름 그대로 사용" 또는 새 닉네임 저장). 비밀번호 가입·소셜 가입 창에서 닉네임을 입력한 계정과 프로필 바에서 닉네임을 바꾼 계정은 1로 기록되어 다시 묻지 않습니다. 다이나믹(컴팩트) 창과 다른 창이 열려 있는 동안에는 띄우지 않습니다. 세션 JSON에 user.nicknameSet 추가(서버 재빌드 필요).

인터넷 검색

  • 대화 두 번째 질문부터 인터넷 검색이 빠지던 문제: 라이브(화면 공유) 상태에서는 첫 질문 때만 서버 화면 분석이 돌고 검색어 제안이 생겼습니다. 이후 질문은 화면이 바뀌지 않았으면 클라이언트가 분석을 건너뛰어(변화 없음/요약 재사용) 검색어 제안 자체가 만들어지지 않았습니다. 이제 화면 단계에서 제안이 없으면 질문 텍스트로 검색어를 제안하는 경로(/api/search/propose, 웹 버전과 같은 승인 카드·1회용 티켓·한도)를 데스크톱·라이브에서도 사용해 대화 중 모든 질문이 검색 대상이 됩니다(화면에서 제안이 있었던 질문은 중복 제안하지 않음).
  • 검색 승인 방식 단순화(사용자 결정): 입력창의 방패/번개 토글 버튼은 "(보류)" 주석으로 숨겼습니다. 대신 라이브를 처음 켤 때(또는 화면과 함께 질문을 처음 보낼 때) "라이브 화면 인터넷 검색 허가" 창이 한 번 떠서 무엇이 전송되는지(화면 이미지는 전송되지 않고 검색어만), 개인정보 필터의 한계, 되돌리는 방법(설정 → 화면 검색 승인 방식)을 설명하고, 허가하고 앞으로 묻지 않기를 누르면 계정 설정에 '승인 무조건 허가'로 저장되어 이후 라이브 화면·질문에서 만든 검색어를 묻지 않고 검색합니다. "매번 확인하기"를 누르면 기존처럼 검색어마다 승인 카드가 뜨고 이 브라우저/앱에서는 다시 묻지 않습니다. 검색어 승인 카드에도 항상 허가 버튼을 추가해 웹에서도 한 번에 전환할 수 있습니다(정적 파일이라 새로고침만으로 반영).
  • 검색어의 긴 숫자열 차단 규칙 제거(사용자 결정): 검색어 개인정보 필터의 전화번호 추정 규칙(7자리 이상 숫자·하이픈·공백 열)이 2026-10-09 같은 날짜, 가격, 수량이 든 검색어까지 통째로 버려 검색이 사라지던 주원인이었습니다. 검색어 생성기에 오늘 날짜를 알려 주기 시작한 뒤 "서울 날씨 2026-10-09"처럼 날짜가 붙은 검색어가 모두 막혔습니다. 사용자 결정에 따라 이 규칙을 제거했습니다(코드에 "(보류)" 주석으로 기록). URL·이메일·파일 경로·IP·API 키·비밀번호 차단은 그대로입니다. 서버 터미널에 search-propose: 검색어 생성 / 필터 차단 / NONE 한 줄을 남겨 다음에 검색이 빠지면 어느 단계인지 바로 볼 수 있게 했습니다(서버 재빌드 필요).
  • 검색을 했는데도 "최신 정보가 없다"고 답하던 문제: 현재 시각 안내문이 "검색 결과가 없으면 날짜를 밝히고 검색을 권하라"고만 적혀 있어 8B 모델이 검색 결과가 붙어 있어도 그 문장을 그대로 따라 했습니다("현재 시각에 대한 정보만 제공할 수 있습니다…"). 안내문을 "검색 결과가 제공되면 그 결과를 최우선 근거로 직접 답하고, 없을 때만 최신 확인 필요를 짧게 밝힌다"로 바꾸고, 검색 성공 상태 안내에 "결과 요약의 수치·사실(기온·강수·가격 등)을 그대로 쓰고 출처 번호를 붙인다, 날씨 앱·다른 사이트에서 확인하라고 답하지 않는다, 결과에 내용이 전혀 없을 때만 무엇이 부족한지 밝힌다"를 추가했습니다(서버 재빌드 필요).
  • 검색 결과를 쓰고도 "최신 정보는 없으며 … 날씨 앱에서 확인하세요" 문단을 덧붙이던 문제: 진단 로그로 검색이 정상(검색어 생성 → 티켓 → 결과 7건 → success)임을 확인했고, 남은 문제는 모델이 답 뒤에 면책 문단을 붙이는 습관이었습니다. ① 시각 안내를 "[현재 시각]" 꼬리표 대신 평서문("오늘 날짜와 시각은 …이다. 언급할 이유가 없으면 언급하지 않는다")으로 바꿔 "현재 시각에 대한 정보만 제공할 수 있다"로 되읊는 빌미를 없앴습니다. ② 검색 성공 상태 안내에 【절대 금지】 문장 목록("최신 정보는 없다", "현재 시각에 대한 정보만", "알려드릴 수 없다", "날씨 앱·웹사이트·인터넷 검색으로 확인하라", "양해 부탁드린다", "실시간 정보를 제공할 수 없다")과 "다시 검색하라고 권하면 오답"을 명시했습니다. ③ 검색 결과 블록 바로 뒤(모델이 마지막으로 읽는 자리)에도 같은 금지 문장과 "결과로 바로 답하라"를 [필수]로 반복합니다. 서버 진단 로그 .data/logs/search.log(단계·건수만, 검색어·본문 없음) 추가(서버 재빌드 필요).

답변 표기·프롬프트

  • 현재 시각 안내문 축소(사용자 결정): 매 답변에 붙는 [현재 시각] 안내에서 "최신 정보가 필요한 질문은 … 최신 확인이 필요하다고 밝히고 검색을 권한다"류 지시를 전부 제거하고 시각 사실과 날짜 계산 기준만 남겼습니다. 8B 모델이 검색 결과가 붙어 있어도 이 지시 문장을 그대로 따라 "최신 날씨 정보는 없으며 … 날씨 앱에서 확인하세요"로 답을 거부하던 원인이었습니다. 검색 결과 사용 지시는 검색 상태 안내(runtime_capabilities)에만 남습니다(서버 재빌드 필요).
  • 강조는 굵게: 매 답변 시스템 지시에 "핵심 결론·주의점·꼭 확인할 이름·수치·단계는 굵게(2~5곳, 문장 전체는 금지)"를 추가했습니다. 웹·앱 렌더러는 이미 …를 굵게 표시합니다(서버 재빌드 필요).

앱 인터페이스·라이브

  • 단축키 표시 통일: 조작 확인·계획·단계·질문 카드의 모든 기본 버튼에 단축키를 표시합니다(계획 허가·시작·기본 선택지·확인 버튼 = Enter, 취소·중지 = Esc, 단계 허가/불허 = 설정된 키). 괄호 "(Enter)" 대신 버튼 글자 뒤 연한 회색 글자로 붙입니다(.key).
  • 다이나믹·앱 패널 스크롤바: 계획 단계 목록·선택지 목록의 스크롤바 흰 트랙을 없애고 투명 트랙 + 얇은 반투명 썸으로 바꿨습니다(control-plan.css).
  • 픽셀 세분화 우선순위(사용자 제안): "RGB 대비가 크고 쓰인 색 수가 적은" 영역(닫기·업로드 버튼, 아이콘, 글자)을 사진·영상·민무늬보다 먼저 세분화합니다. 점수 = 밝기 5~95 백분위 폭 × (1 − 색 비율). 적용 지점 두 곳: ① 라이브 변화 영역 크롭(프레임당 최대 4개) — 지금까지는 화면 순서(좌상→우하)대로 4개를 잘라 우측 하단 썸네일 같은 작은 위젯이 빠질 수 있었는데, 후보가 4개를 넘으면 점수 순으로 고릅니다(live-grid.widgetScore/prioritize). ② 서버 확대 분석(zoom) — 모델이 제안한 확대 후보를 최대 6곳 받아 점수 상위 3곳만 확대합니다(vision.widget_score/rank_regions). 후보가 한도 이하일 때는 동작이 바뀌지 않으며, 검증 테스트(버튼 0.69 > 글자 0.33 > 사진·민무늬 0.0)를 추가했습니다. 모델 판단 자체를 바꾸지는 않으므로 효과는 "한도 초과 시 무엇을 먼저 보여 주는가"에 한정됩니다.

요금제·환불

  • 환불 규칙(사용자 결정): 결제 후 7일 이내이거나 그 결제 기간 사용량이 100만 토큰 이하이면 조건 없이 환불됩니다. 요금제 창의 환불 신청 버튼(유료 상태일 때만 표시)이 자격을 미리 확인해 보여 주고, 신청하면 유료 기능이 즉시 해제되고 환불 기록이 남습니다(refunds 표, 관리자 GET /api/admin/refunds). 결제 모듈이 아직 연결되지 않아 실제 송금은 운영자가 환불 목록을 보고 처리합니다.
  • 환불 남용 방지: 환불 때 접속 IP(Cloudflare CF-Connecting-IP)를 키 기반 해시로만 보관하고(원문 저장·복원 불가), 30일보다 오래된 기록은 자동 삭제합니다. 30일 안에 같은 IP 해시의 환불이 4회 이상이면 그 계정의 이용을 제한(users.banned)하고 세션을 끊으며, 제한 직후 그 IP 기록을 즉시 파기합니다. 제한된 계정은 로그인해도 "환불 남용으로 이용이 제한된 계정" 안내만 받습니다. 요금제 창에 규칙 문구를 넣었습니다.

유료 전용 화면 기능(사용자 결정)

  • 컴퓨터 조작은 유료·1개월 무료체험 전용입니다. 무료 계정은 서버가 403으로 거부하고 "요금제 창에서 무료체험을 시작해 주세요"를 안내합니다.
  • 라이브 화면 분석은 무료 계정에 하루 3회 맛보기만 허용합니다(질문과 함께 보내는 분석 기준, 배경 관찰은 세지 않음). 그 뒤에는 유료·무료체험 안내.

다이나믹·앱

  • 다이나믹 열기/접기 프레임: 16ms 고정 타이머 대신 다이나믹이 놓인 모니터 주사율에 맞춰 프레임 간격을 정합니다(60Hz → 열기 13·접기 25프레임, 120Hz ProMotion → 26·50프레임). 시간 기준 보간이라 길이(열기 220ms·접기 420ms)는 그대로입니다.
  • 업데이트 로그 화면: GitHub 대신 앱·웹 안에서 봅니다. 새 버전을 처음 켜면 자동으로 뜨고, 앱 상단의 두루마리(업데이트 로그) 버튼(기존 "내 컴퓨터" 버튼 자리, 진단 창은 보류)과 "Alpha 1 ▾" 창의 "업데이트 내역 보기"에서 언제든 다시 엽니다. 과거 모든 버전(1.1.7~)을 왼쪽 버전 목록에서 골라 볼 수 있고, 배너·섹션 카드 구성은 Roblox TDS 업데이트 로그 느낌을 Alpha 하늘색 팔레트로 옮겼습니다. 배포 스크립트가 web/release-history.json을 모든 CHANGES-*.md에서 만듭니다.
  • 개인 프롬프트 픽토그램을 메인 프롬프트와 같은 터미널 아이콘으로 바꿨습니다.
  • (보류) 오류 감지 즉시 팝업: 설계(별도 네이티브 감시 에이전트 ≤50MB, 충돌 보고서·응답 없음·오류 대화상자·반복 종료 감지 규칙, 서명 토큰 소켓 호출, 유료 확인)와 코드를 desktop/error-watch.cjs에 전부 주석으로 남겼습니다. 감지 뒤 "고치기"는 조작 모델 보류 결정과 같은 이유로 컴퓨터 업그레이드 후 되살립니다.

배포 도구

  • 게시 실패가 "배포된 것처럼" 보이던 문제: GitHub 게시(토큰 입력·업로드·다운로드 페이지 갱신) 단계가 실패해도 서버가 그대로 다시 시작되어 성공처럼 보였고, 같은 번호로 다시 게시하려면 번호를 또 올려야 했습니다. 이제 게시 단계가 실패하면 터미널에 !!! GitHub 게시 실패 경고를 크게 표시하고 .data/releases/current/UNPUBLISHED 표시를 남깁니다. 새 VS Code 작업 Alpha: 준비된 배포본 GitHub 게시만(--publish-only)은 이미 빌드된 같은 번호의 배포본을 빌드 없이 GitHub에 게시하고 다운로드 페이지까지 갱신합니다. 다운로드 페이지(github.io)는 게시 성공 직후 자동으로 같은 버전으로 바뀝니다.
  • 업데이트 로그 화면은 전체 이력(release-history.json)을 못 받으면 현재 버전의 release.json만으로라도 표시하고, 실패 원인(HTTP 코드)을 안내에 붙입니다.

Windows x64, macOS Apple Silicon/Intel 설치 파일은 미서명 개발용 빌드입니다.

설치·업데이트

  • Windows: Setup.exe를 열고 설치를 완료한 뒤 바탕화면 또는 시작 메뉴에서 Alpha AI를 실행하세요.
  • macOS: .pkg를 실행하면 /Applications/Alpha AI.app을 설치·교체합니다. 응용 프로그램에서 새 앱을 실행하세요.
  • 기존 사용자: 메뉴 막대 또는 시스템 트레이에서 Alpha를 종료한 뒤 설치하세요. 기존 앱 삭제는 필요 없으며 로그인·설정 데이터는 보존됩니다.
  • 앱의 업데이트 안내 또는 설정 → 업데이트 확인에서 새 설치 프로그램을 열 수 있습니다. 사용자 확인 없이 자동 설치되지는 않습니다.
  • macOS 화면 권한이 거부되면 시스템 설정의 화면 기록 권한을 확인하고 앱을 다시 실행하세요.

화면 공유와 검색

운영체제 화면 권한과 화면 전송 동의가 필요합니다. 라이브 중 처음 화면과 변경된 화면은 Alpha 서버에서 분석하며 요금제 사용량이 적용됩니다. 변화 없는 화면은 재사용하지만 새 질문의 세부 확인에는 추가 분석이 필요할 수 있습니다. 라이브 종료 또는 화면 내용 포함 끄기로 전송을 중지할 수 있습니다.

원본 이미지는 대화 DB에 저장하지 않으며 질문에 사용한 설명은 대화에 남습니다. 비교용 캐시는 메모리에만 유지하고 만료·종료 시 해제합니다. 사용자가 켠 별도 녹화 저장은 유지됩니다. HTTPS 중계 서비스가 통신을 처리할 수 있습니다.

승인 검토에서는 검색어와 제공업체를 확인한 뒤 허가합니다. 승인 무조건 허가는 별도 확인 후 저장되며 화면 분석 기반 검색에만 적용됩니다. 검색어에는 민감 정보가 포함될 수 있으므로 승인 전에 확인하세요.

파일 찾기

유료·활성 무료체험 계정에서 허용한 폴더의 파일을 찾아 Finder·탐색기에 표시하고 삭제·이동 방법을 안내합니다. 파일 내용과 절대 경로는 전송하지 않으며 선택 파일 이름·상대 위치를 AI에 보내는 작업은 별도 동의를 받습니다. 실제 삭제·이동·실행은 자동 수행하지 않습니다. 폴더 권한은 철회할 수 있습니다.

모바일·배포 안내

휴대폰에서는 모바일 웹 대화를 이용할 수 있습니다. iPhone·Android 설치 파일, 다이나믹 아일랜드·상단 알림 연동, App Store·Google Play 출시는 아직 제공되지 않습니다.

현재 개발용 미서명 빌드입니다. macOS 정식 배포 서명·공증과 Windows 코드 서명은 없으며 Windows·Intel 실기기 설치 검증은 남아 있습니다. AI 대화에는 운영자 서버 연결이 필요합니다.

이 저장소는 앱 배포 파일과 이용 안내만 제공합니다. 서버 개발 소스와 사용자 데이터는 공개하지 않습니다.
