기본 설정에 "시작하면 다이나믹 표시" (사용자 요청 2026-10-13, 앱·웹 화면)

  • 테스트 main-integration.test.cjs 갱신, 데스크톱 308개 통과. 10개 언어 문구 추가.

시간 기능 — 답변 모델이 직접 도구를 호출 (사용자 결정 2026-10-13, 옵션 1; 서버)

  • 지금까지는 질문마다 별도 분류 호출(약 10초) → 규칙 계산 → 카드였고, 이전 대화 맥락을 못 봤습니다. 이제 답변 모델이 대화 맥락을 보면서 필요할 때 스스로 시간 도구를 부릅니다(Hermes 함수 호출 형식 <tool_call>: set_timer · set_alarm · add_event · list_events · delete_event · stopwatch · schedule_action). 서버는 그 호출을 기존 확인 카드로 올리고, 허가 전에는 아무것도 바꾸지 않습니다. 도구 호출 JSON 은 화면·기록에 보이지 않습니다.
  • 질문당 모델 호출은 1회(분류 호출 제거). 일정 조회(list_events)만 자료를 받아 한 번 더 답합니다. 모델이 도구를 안 부르고 글로만 답하면 규칙(time_intent)이 보조로 카드를 붙입니다. "그거 5분으로 바꿔" 같은 후속 요청도 모델이 맥락으로 처리합니다(8B 모델 특성상 가끔 놓칠 수 있고, 그때는 규칙이 받습니다).
  • 규칙 보조 수정: "타이머 울리기" 에서 '기' 같은 가짜 이름을 만들지 않음(이름은 따옴표·"X 이름의"·"X(이)라는"·"X 타이머/알람" 처럼 분명할 때만), 한글 숫자("일분 뒤", "삼십분", "한 시간") 인식.
  • 남은 지연: 검색 승인 '검토' 모드에서는 질문을 보내기 전에 검색어 생성 호출(/api/search/propose, 로그상 3~23초)이 먼저 돕니다. 이는 별도 결정 사항이라 그대로 두었습니다.
  • 테스트 tests/test_time_tools.py(6: 스트림에서 도구 호출 가리기, 매핑, 같은 대화에서 2·3번째 요청도 카드, 규칙 보조, 조회 2차 답변), 기존 테스트 갱신. Python 265개(test_native 제외) 통과.

스톱워치 Space 키로 정지가 안 되던 문제 (사용자 보고 2026-10-13, 웹·앱 화면)

  • 시작 버튼을 누른 뒤 화면을 다시 그리면 포커스가 사라져 Space 가 시간 창에 닿지 않았습니다. 시간 창이 열려 있고 스톱워치 탭이면 어디서든 Space 로 시작·정지되고(입력칸 제외), 다시 그린 뒤 토글 버튼에 포커스를 둡니다.

Mac ↔ Windows 캘린더 양방향 허브 (사용자 결정 2026-10-13, 옵션 1; 서버·앱)

  • 지금까지는 각 기기가 자기 OS 일정만 Alpha 에 올리고 Alpha 에서 만든 일정만 자기 OS 캘린더에 써서, Mac 캘린더 일정이 Windows 캘린더에 나타나지 않았습니다. 이제 서버가 허브가 되어 어느 기기의 OS 일정이든 다른 모든 기기의 OS 캘린더에 써 넣고, 한 기기에서 고치거나 지우면 다른 기기에도 전파합니다(수정은 그 기기의 OS id 로 갱신, 삭제는 묘비로 남겨 모든 기기에서 지운 뒤 정리).
  • 서버: calendar_links(일정 × 기기 → OS id, pushed)·time_sync_devices(기기별 동기화 상태) 표 추가, apply_sync/acknowledge_sync 가 기기 표식(X-Alpha-Device)별로 동작. 구버전 앱(표식 없음)은 legacy:<platform> 기기로 취급하고, 같은 플랫폼의 첫 새 앱이 그 링크를 이어받습니다(마이그레이션 멱등). /api/time/sync 응답 sync.devices 에 기기 목록.
  • 앱: 동기화 요청에도 기기 표식 헤더를 붙이고 ack 에 platform 을 포함(time-sync.cjs). Windows 는 AppointmentStore 쓰기 권한이 있는 환경에서만 써 넣습니다(기존 제약).
  • 테스트 test_timekeeping.CalendarHubTests(2: 양방향 흐름·수정·삭제 전파, 구버전 링크 승계), 기존 단일 기기 테스트 유지, time-sync.test.cjs 갱신. Python 267개(test_native 제외)·데스크톱 308개 통과.

설치·업데이트

  • Windows: Setup.exe를 열고 설치를 완료한 뒤 바탕화면 또는 시작 메뉴에서 Alpha AI를 실행하세요.
  • macOS: .pkg를 실행하면 /Applications/Alpha AI.app을 설치·교체합니다. 응용 프로그램에서 새 앱을 실행하세요.
  • 기존 사용자: 메뉴 막대 또는 시스템 트레이에서 Alpha를 종료한 뒤 설치하세요. 기존 앱 삭제는 필요 없으며 로그인·설정 데이터는 보존됩니다.
  • 앱의 업데이트 안내 또는 설정 → 업데이트 확인에서 새 설치 프로그램을 열 수 있습니다. 사용자 확인 없이 자동 설치되지는 않습니다.
  • macOS 화면 권한이 거부되면 시스템 설정의 화면 기록 권한을 확인하고 앱을 다시 실행하세요.

화면 공유와 검색

운영체제 화면 권한과 화면 전송 동의가 필요합니다. 라이브 중 처음 화면과 변경된 화면은 Alpha 서버에서 분석하며 요금제 사용량이 적용됩니다. 변화 없는 화면은 재사용하지만 새 질문의 세부 확인에는 추가 분석이 필요할 수 있습니다. 라이브 종료 또는 화면 내용 포함 끄기로 전송을 중지할 수 있습니다.

원본 이미지는 대화 DB에 저장하지 않으며 질문에 사용한 설명은 대화에 남습니다. 비교용 캐시는 메모리에만 유지하고 만료·종료 시 해제합니다. 사용자가 켠 별도 녹화 저장은 유지됩니다. HTTPS 중계 서비스가 통신을 처리할 수 있습니다.

승인 검토에서는 검색어와 제공업체를 확인한 뒤 허가합니다. 승인 무조건 허가는 별도 확인 후 저장되며 화면 분석 기반 검색에만 적용됩니다. 검색어에는 민감 정보가 포함될 수 있으므로 승인 전에 확인하세요.

파일 찾기

유료·활성 무료체험 계정에서 허용한 폴더의 파일을 찾아 Finder·탐색기에 표시하고 삭제·이동 방법을 안내합니다. 파일 내용과 절대 경로는 전송하지 않으며 선택 파일 이름·상대 위치를 AI에 보내는 작업은 별도 동의를 받습니다. 실제 삭제·이동·실행은 자동 수행하지 않습니다. 폴더 권한은 철회할 수 있습니다.

모바일·배포 안내

휴대폰에서는 모바일 웹 대화를 이용할 수 있습니다. iPhone·Android 설치 파일, 다이나믹 아일랜드·상단 알림 연동, App Store·Google Play 출시는 아직 제공되지 않습니다.

현재 개발용 미서명 빌드입니다. macOS 정식 배포 서명·공증과 Windows 코드 서명은 없으며 Windows·Intel 실기기 설치 검증은 남아 있습니다. AI 대화에는 운영자 서버 연결이 필요합니다.

이 저장소는 앱 배포 파일과 이용 안내만 제공합니다. 서버 개발 소스와 사용자 데이터는 공개하지 않습니다.
