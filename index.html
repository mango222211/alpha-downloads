  • 원인: 4.15.16 허브 전환 때 구버전 연동 링크에 플랫폼을 붙이면서 "마지막으로 동기화한 기기"(Windows)를 기준으로 삼아, Mac 일정의 링크가 legacy:windows 로 잘못 표시됐습니다. 새 Mac 앱이 동기화하자 자기 일정을 못 알아보고 다시 들여왔고(Alpha 2배), 옛 행들을 "Mac 에 없는 일정"으로 보고 Mac 캘린더에 복사본을 써 넣었습니다(Mac 2배).
  • 수정 ① 재발 방지: 기기 링크가 없으면 플랫폼 표시와 무관하게 같은 OS id 를 가진 구버전 링크·구버전 external_id 열을 먼저 찾아 이 기기 것으로 잇습니다. ② 복구(서버 시작 때 자동, 멱등): Apple 꼴 id 의 구버전 링크를 legacy:macos 로 바로잡고, 제목·시각이 같은 중복 일정 가운데 구버전 링크가 붙은 옛 행을 묘비로 만들어 다음 동기화에서 Alpha 가 써 넣었던 복사본만 Mac 캘린더에서 지웁니다(사용자의 원본 일정은 남김). Alpha 목록도 하나로 돌아옵니다.
  • 테스트 CalendarHubTests 2개 추가(잘못 표시된 구버전 링크, 사고 모양 복구). 배포 후 Mac 앱이 한 번 동기화(시간 메뉴 열기 또는 5분)하면 정리됩니다.

화면 공유와 검색

운영체제 화면 권한과 화면 전송 동의가 필요합니다. 라이브 중 처음 화면과 변경된 화면은 Alpha 서버에서 분석하며 요금제 사용량이 적용됩니다. 변화 없는 화면은 재사용하지만 새 질문의 세부 확인에는 추가 분석이 필요할 수 있습니다. 라이브 종료 또는 화면 내용 포함 끄기로 전송을 중지할 수 있습니다.

원본 이미지는 대화 DB에 저장하지 않으며 질문에 사용한 설명은 대화에 남습니다. 비교용 캐시는 메모리에만 유지하고 만료·종료 시 해제합니다. 사용자가 켠 별도 녹화 저장은 유지됩니다. HTTPS 중계 서비스가 통신을 처리할 수 있습니다.

승인 검토에서는 검색어와 제공업체를 확인한 뒤 허가합니다. 승인 무조건 허가는 별도 확인 후 저장되며 화면 분석 기반 검색에만 적용됩니다. 검색어에는 민감 정보가 포함될 수 있으므로 승인 전에 확인하세요.

파일 찾기

유료·활성 무료체험 계정에서 허용한 폴더의 파일을 찾아 Finder·탐색기에 표시하고 삭제·이동 방법을 안내합니다. 파일 내용과 절대 경로는 전송하지 않으며 선택 파일 이름·상대 위치를 AI에 보내는 작업은 별도 동의를 받습니다. 실제 삭제·이동·실행은 자동 수행하지 않습니다. 폴더 권한은 철회할 수 있습니다.
